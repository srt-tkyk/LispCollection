# S式ゲノム — なぜ人工生命を Lisp で書くのか

## 中心の主張

人工生命のシミュレーションにおいて、Lisp には他の言語にない固有の適性がある。
それは速度でも表現力一般でもなく、**「生物の記述」と「生物の実体」を
同じ表現で書けること**にある。

von Neumann が自己増殖オートマトンを考えたとき、彼は2つのものを必要とした。
受動的な**記述**（テープ、設計図）と、それを読んで組み立てる能動的な**構成器**である。
生物における DNA と細胞機構の関係がこれにあたる。同じ分子列が、
複製されるときは受動的なデータであり、転写されるときは能動的な指令になる。

Lisp の `quote` と `eval` は、まさにこの対をなす。

```lisp
'(if (< (dist-to-food) 40) (steer-to-food) (wander))   ; データ — 変異・交叉の対象
(eval '(if (< (dist-to-food) 40) ...))                 ; 実行 — 表現型としての振る舞い
```

同一のリストが、遺伝子型でもあり表現型の記述でもある。
この一致は Lisp の設計思想（homoiconicity）から直接くるものであって、
人工生命のために後から作った仕掛けではない。

このプロジェクトは、その主張を実装で確かめたものである。

---

## 出発点 — 何が問題だったか

元のシミュレーション `evolve.lisp` は、素直で綺麗な実装だった。
500×500 のトーラス世界で、5次元のゲノムを持つ個体がエネルギー収支で淘汰される。

```lisp
(defstruct genome speed turn-rate metabol sense-r hue)
```

行動はこう書かれていた。

```lisp
(if food (steer-toward org food ...) (wander org ...))
```

ここで**誰が何を決めているか**を分けると、問題がはっきりする。

- **人間が決めたもの**: 「餌が見えたら向かう、見えなければふらつく」という判断の形。
  この `if` は手で書かれている。
- **進化が決めるもの**: `speed` が 1.2 か 2.4 か、`sense-r` が 40 か 90 か、という数値だけ。

`mutate` 関数は5つの数値それぞれにガウスノイズを足すだけで、
`behave` の中身を一文字も書き換えない。

つまり**進化は数値を担当し、人間は構造を担当する**という分業が固定されている。

この設計では、次のような行動は何万世代回しても現れない。

- エネルギーが少ないときだけ餌を追い、十分なときは休息する（条件が入れ子になる）
- 他個体の方へ寄る（新しい感覚入力の使い方）
- 前回の進行方向を覚えて反転を避ける（内部状態の利用）

これらは φ: ℝ⁵ → 行動空間 という写像の**像の外**にある。
進化はその5次元の像の上を登るだけで、像そのものは動かせない。

これは `evolve.lisp` の欠陥ではなく、**固定次元ゲノムという設計の帰結**である。
そして同じ設計であれば、Python でも C でも Lisp でも実装は変わらない。
つまりこの段階では、Lisp を使う理由が何もない。

## 転換 — ゲノムをプログラムにする

行動そのものを S 式の木としてゲノムに入れる。

```lisp
(defstruct genome
  speed turn-rate metabol sense-r hue    ; 形態 — 連続値
  aggression                             ; 攻撃性
  turn-tree                              ; 脳1 — 旋回量を決める木
  speed-tree)                            ; 脳2 — 速度を決める木
```

すると `mutate` の仕事が変わる。数値を揺らすのではなく、木の一部を差し替える。

```lisp
;; 親
(if> (food-dist) 0.5 (steer) (wander))
;; 変異が (wander) を新しい if> に置き換えた
(if> (food-dist) 0.5 (steer) (if> (energy) 0.2 (steer) (rest)))
```

**この変異は、人間が書いていない構造を作り出した。**
さきほど「絶対に出現しない」と書いた行動が、変異1回で生まれている。

交叉も同じことが起きる。

```lisp
;; 親A                              ;; 親B
(if> (food-visible) (steer) (wander))  (if> (energy) 0.2 (rest) (wander))
;; 条件部を交換した子 — どちらの親も持たない行動
(if> (energy) 0.2 (steer) (wander))
```

### 空間の形が変わる

- **固定次元**: G = ℝ⁵。次元は永遠に 5。表現型写像 φ は固定された1本の射。
- **S式**: G = 自由 Σ 代数 T_Σ(X)。サイズ n の項の個数は指数的に増え、n に上限がない。
  そして `eval` は始代数からの一意な準同型そのものである。

後者は「プリミティブ集合 Σ の合成閉包」を探索している。
Σ が有限でも閉包は非有界なので、**次元という概念が消える**。
これが「今まで存在しなかった行動」の出どころである。

## なぜ Lisp か — 他言語との比較

「実行時にプログラムを作って動かす」こと自体は、Lisp の専売特許ではない。
違いは**そのコストがどこに現れるか**にある。

| | 実行時に木→実行可能 | 遺伝子の表現 | 実際に払うコスト |
|---|---|---|---|
| C / C++ / Rust | 不可 | 自前 VM のオペコード列 | **自前 ISA と逆アセンブラを書く** |
| Python | 可 | 専用 AST ノード or 文字列 | **木⇄コードの変換器を書く** |
| JavaScript | 可 | 文字列 | 構造の保証がない |
| Haskell (GADT) | 実質不可 | 型で閉じた項 | 型制約が探索空間も削る |
| **Common Lisp** | **可** | **リスト = ソース** | **変換器が要らない** |

補足すると:

**C 系の解法が Tierra / Avida である。** 彼らは自前の仮想機械とアセンブリ ISA を
定義して解釈実行する。実際にうまくいっているが、シミュレータに加えて
言語処理系も作ることになり、プリミティブ集合はオペコード表で固定される。

**Python は本当にできる。** 興味深いのは、遺伝的プログラミングのライブラリ DEAP が
Python 標準の `ast` を使わず、`Primitive` オブジェクトの前置記法リストを持って
文字列連結してから `eval` している点である。つまり実務的な解として
**S 式を再発明している**。`ast.BinOp` を visitor パターンで書き換えるのが
苦痛すぎるからだ。

**Haskell の型付き GP は Lisp に対する明確な優位点である。**
GADT で `Term a` を作れば、ランダムな部分木交換が型検査を通る組み合わせしか
作れず、無効個体が構造的にゼロになる。代償は、型制約が探索空間を大きく削ること。
ゴミが減る反面、開放性も減る。ここはトレードオフであり、Lisp が一方的に
勝っているわけではない。

**Common Lisp の固有性は「同一表現 × ネイティブコンパイル」の組み合わせにある。**
`(+ 1 2)` は3要素のリストであり、保存形式であり、変異対象であり、ソースコードでもある。
パーサもシリアライザも要らず、`print` した系統がそのまま人間可読で、`read` で戻せる。
そして SBCL は木を数ミリ秒で機械語に変換する。

実装では、木をソースに変換する `emit` 関数の中身が、
`%`（保護付き除算）と `if>` の2つを除いて**ほぼ恒等写像**になる。

```lisp
(t (cons (car tree) (mapcar #'emit a)))   ; 大半はこれだけ
```

Python は前半（実行時生成）だけ、C は後半（ネイティブ速度）だけを持っている。

## 実装したもの

```
brain.lisp       S式ゲノム — 木の生成・変異・交叉・コンパイル
spatial.lisp     トーラス空間ハッシュ
alife-clos.lisp  シミュレーション本体（CLOS）
lineage.lisp     系統の記録・S式の差分・行動の応答面
viz.lisp         可視化 — SVG 生成と単一 HTML レポート
render.lisp      PPM 出力 + ffmpeg で MP4 化
```

外部ライブラリへの依存はない。素の SBCL で動く。

### プリミティブ集合

終端: `food-angle` `food-dist` `energy` `age` `noise` + エフェメラル定数
関数: `+ - * %` `if>` `sin` `abs`

すべて `single-float` を返す（**閉包性**）。
よって任意の部分木を任意の位置に差し込んでも妥当な木になり、
交叉・変異に型チェックが要らない。

### CLOS — 同じ脳が体によって別の意味を持つ

知覚対象を多重ディスパッチで決める。

```lisp
(defmethod edible-p ((e herbivore) (thing food))      t)
(defmethod edible-p ((e predator)  (thing herbivore)) t)
(defmethod edible-p ((e predator)  (thing predator))  nil)
```

草食獣の `FOOD-ANGLE` は植物への方向、捕食者の `FOOD-ANGLE` は獲物への方向を指す。
`change-class` で種が変わると、**脳の S 式を一文字も書き換えずに行動の意味が変わる。**
遺伝子は同じで解釈系が変わる、という構図がそのままコードになっている。

種分化は `change-class` で実装した。オブジェクトを作り直さないので
`EQ` 同一性が保たれ、世界のリストや進行中の参照が壊れない。
遷移処理は CLOS 標準プロトコルに乗る。

```lisp
(defmethod update-instance-for-different-class :after
    ((old herbivore) (new predator) &key)
  (setf (genome-hue (organism-genome new)) 0.0))   ; 赤くなる
```

生態的相互作用は本質的に二項関係（捕食者×被食者、個体×資源）なので、
多重ディスパッチが素直にはまる。新種の追加は既存コードに触れずにメソッドを
増やすだけで済む。

## 観測されたこと

### 1. 感覚運動結合が書かずに発見された

餌が潤沢な環境で 1200 tick 走らせると、`turn-tree` が `food-angle` を参照する
個体の割合が **56% → 100%** に上昇し、平均脳サイズは 24.6 → 12.3 に縮小した。

生き残った脳:

```lisp
turn : FOOD-ANGLE
speed: FOOD-DIST
```

元の `evolve.lisp` の `steer-toward` に相当する行動が、一行も書かずに発見され、
しかも脳の維持コスト（代謝に木のサイズ分を加算）によって**最小形まで削られた**。

### 2. 条件分岐は環境が要求したときだけ現れる

周期的な飢饉を入れ、移動コストを速度の2乗にすると:

```
条件分岐 (if>) を持つ個体:     51% → 100%
speed-tree が energy を参照:   53% → 100%
```

一方、餌が潤沢な 1 の環境では `if>` は **0% まで淘汰された**。
「エネルギーが少ないときだけ動く」戦略は、飢饉がある環境でのみ価値を持つ。

### 3. 捕食が自然発生し、Lotka-Volterra 振動が生じた

`aggression` 遺伝子が閾値を超えると `change-class` で捕食者になる設定で、
2000 tick:

```
Tick  300 | 草食  129 | 捕食   1     ← 最初の捕食者
Tick 1500 | 草食  543 | 捕食  57     ← ピーク
Tick 1600 | 草食  578 | 捕食  22     ← 獲物減で追随して減少
Tick 2000 | 草食  573 | 捕食  27
種転換: 617 回 (→捕食 601 / →草食 16)
```

seed 1/2/3 のいずれでも捕食者が定着した。草食化が16回あるのは
`change-class` が可逆に効いている証拠である。

### 4. 遺伝子型距離と表現型距離は一致しない

```lisp
(+ (* ENERGY 2.0) FOOD-ANGLE)     ; 親
(+ FOOD-ANGLE (* ENERGY 2.0))     ; 子 — 木としては別物
→ 応答面 RMS 差 0.0000            ; 行動は完全に同一（中立変異）
```

木の図だけを見ていては、S 式が違っても行動が同じであることは分からない。
そこで `food-angle` × `food-dist` の格子で脳を評価し、旋回量を色で塗る
**応答面**を可視化に組み込んだ。遺伝子型ではなく表現型を直接見るための道具である。

## うまくいかなかったこと

実装の途中で得られた否定的な結果も、同じくらい重要なので記録しておく。

**捕食者が一度も出現しなかった。** 初期設定では `aggression` の閾値を 0.75 に
していたが、この遺伝子は閾値を超えるまで**完全に中立**なので、
適応度平原をランダムウォークで渡りきれない。閾値 0.55・変異幅5倍で渡れるようになった。
「開放的な遺伝子型空間があれば何でも進化する」わけではない。

**閾値を下げただけの版では共倒れした。** 捕食者が獲物を食い尽くし、
t=900 で草食7・捕食182 → t=1221 全滅。捕獲を確率的にし、捕食者の捕獲半径を
下げ、維持費を2倍にしてようやく共存した。**共存はパラメータ空間の狭い領域にある。**

**空間ハッシュの効果が限定的だった。** 1000 オブジェクトで全走査比 2 倍
（1.17 秒 → 0.60 秒 / 30 tick）止まり。感知半径が最大 130 で世界の幅 500 に対して
大きすぎ、クエリが格子の大半を舐めている。

**bloat が再発した。** 個体数が上限に達すると選択圧が弱まり、
脳サイズが 22 → 39 に増加した。維持コストを個体数依存にする必要がある。

## 主張の限界

S 式ゲノムにしても、**自動的に何でも進化するわけではない。**

プリミティブ集合 Σ は結局人間が手で選ぶ。内部状態を持つ部品を入れなければ
記憶は進化しないし、他個体を参照する述語がなければ群れも出ない。
このプロジェクトの実装にはどちらも入っていないので、
記憶に依存する戦略も群れ行動も**原理的に出現しない**。

つまり、固定次元では「行動」を決め打ちしていたのが、
S 式では「**語彙**」を決め打ちすることに変わっただけ、とも言える。

変わったのは、語彙の合成閉包が非有界だという一点である。
それが質的に大きいというのがこのプロジェクトの立場だが、
「開放的進化を実現した」と言えるほどのものではない。

また、Lisp が適しているのは**遺伝子がプログラムである場合**に限られる。
ゲノムが実数ベクトルや固定長ビット列であるようなシミュレーション
（多くの人工生命研究がそうである）では、Lisp を使う積極的な理由はない。
主張の射程は思ったより狭い。

## 副次的に得られたもの

S 式であることの利得は、進化そのもの以外にも現れた。

**ログにパーサが要らない。** 全個体のゲノムを `print` で書き出し、
`read` で戻せる。シリアライザもパーサも書いていない。

**進化した脳がそのまま読める。** `show-brains` は生存個体の脳を
Lisp のソースコードとして印字する。何が進化したのかを人間が直接検分できる。
機械語やニューラルネットの重み行列ではこうはいかない。

**走らせたまま世界に介入できる。** REPL でシミュレーションを止めずに
`metabolic-cost` を再定義すると、次の tick から効く。
観測者が現象を止めずに触れる、という構図がそのまま使える。

```lisp
(dotimes (i 500) (world-step *w*))
(defmethod metabolic-cost ((org predator) v) (* 1.2 (call-next-method)))
(dotimes (i 200) (world-step *w*))   ; 環境を変えた後の応答を見る
```

**可視化も Lisp 側で完結する。** SVG を Lisp が生成して HTML に埋め込むので、
JSON 化もクライアント側描画も要らない。単一ファイル・外部依存ゼロのレポートになる。

## まとめ

「Lisp は人工生命に適している」という主張を、条件つきで支持する結果になった。

**適している条件**: 遺伝子がプログラムであること。
このとき Lisp は、遺伝子型・表現型・保存形式・人間可読な記述の4つを
単一の表現でまかない、しかもネイティブコードにコンパイルできる。
他の言語はこのうちどれかを諦めるか、変換層を自作することになる。

**適していない条件**: 遺伝子が数値ベクトルであること。
このときは他の言語と何も変わらない。

そして、S 式ゲノムを採用しても、進化が探索できる範囲は
人間が選んだプリミティブ集合の合成閉包に閉じている。
Lisp が与えるのは「構造を進化させる自由」であって、「開放性そのもの」ではない。
